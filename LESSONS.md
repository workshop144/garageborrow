# Lessons

One line per lesson, newest first.

- 2026-11-06: `deploy.yml` set up the OIDC deploy role before `sam build`, and no function set a `BuildMethod`, so SAM's default Node builder would have run `npm install` (no lockfile, install scripts, no release-age cooldown) with prod credentials in the environment; only the `workspace:*` dependency making npm fail kept it latent. The first fix only moved the credentials step, which is not enough: `id-token: write` on a job lets every step in it (install scripts, build plugins) request the OIDC token and assume the role itself. Rule: `sam build` only copies each handler's own `pnpm build` bundle (`BuildMethod: makefile`, `apps/api/Makefile`); install and build run in a job without `id-token` or the production environment, and the job that holds `id-token` checks out and installs nothing (pinned deploy actions, the build artifact, `sam`/`aws` only); the role trusts exactly `environment:production`; a deploy fails closed when a bundle imports a module the Lambda will not have (`scripts/check-lambda-externals.mjs`); every CI tool installer pins an exact version (sec/2026-11-06c, S4-3, PR #46).
- 2026-11-06: `.gitleaks.toml` allowlisted `paths = ['docs/deploy\.md']` to quiet one example key, and gitleaks ORs paths with regexes, so the deploy playbook (where a real key is most likely to be pasted) was never scanned. `condition = "AND"` on a global allowlist does not fix it in gitleaks 8.30.1 (paths still skip the whole file). Rule: allowlist exact secrets with `regexes`, never `paths`; `scripts/gitleaks-config-test.sh` proves a pasted key in docs/deploy.md is reported (sec/2026-11-06c, S4-2).
- 2026-11-06: pnpm's lockfile, 3-day release age and `allowBuilds` covered every dependency except Lighthouse, which CI fetched fresh with `npx --yes` on every run. Rule: every tool CI or a script runs is a pinned devDependency run with `pnpm exec`, never `npx`/`dlx`; CI-only tools live in a `tools/*` workspace package that deploy.yml's install filters out; every workflow checkout sets `persist-credentials: false` and workflows default to a read-only `permissions` block (sec/2026-11-06c, S4-1, PR #44).
- 2026-11-06: pino redacted phones in logs, but the error boundary sent the concrete request path to Sentry, and admin routes carry the member's phone (`/admin/members/:phone`), as do the browser's fetch breadcrumbs. Rule: anything sent to a third-party processor goes through `scrubPhonesDeep` (`@garageborrow/shared/scrub-phones`), and every `Sentry.init` keeps its `beforeSend`/`beforeBreadcrumb` scrubbers (sec/2026-11-06c).
- 2026-11-06: Wishlist, donations and uploads had daily caps, but borrow requests and reservations did not, and reservations had no length limit or owner release. One member could use up the owner's 5/day notification budget or hold every unit until year 9999. Rule: every member-created row that pings the owner or holds a unit gets a `bumpWindowCounter` daily cap, a duplicate/open-row limit and a time bound, and every state an owner cannot leave through the app is a bug (sec/2026-11-06c).
- 2026-11-06: The members directory hid hidden and leaving members, but the wishlist masked phones to last 4 without checking visibility, and one route had its own looser photo-key regex. Rule: every member-facing view of another member uses the /members predicate (`visible` and no `deleted_at`), and photo keys are checked only with the shared `PHOTO_KEY_RE` (`@garageborrow/shared/photo-key`, imported by API and web) and rendered only through `photoUrl()` (sec/2026-11-06c).
- 2026-11-06: `/v1/me` returned raw membership rows, so members read the owner's private notes and their hidden tier, and the data export held one profile row. Rule: member-facing endpoints return an explicit projection, never a stored row, and the export is built from the same entity list the account cleaner scrubs (sec/2026-11-06c).
- 2026-11-06: The 48h return auto-confirm existed and had tests, but nothing scheduled it, so claimed returns stayed active forever and reminders kept firing. Rule: every sweep helper is called from a scheduled entry point and has a test through that entry point (fix/bugs-2026-11-06).
- 2026-11-06: Loan, donation and idempotency writes were read-check-then-unconditional-Put, so concurrent requests lost updates or ran twice. Rule: a state transition is a conditional write on the state that was read (`rev`, `#status = :expected`, `attribute_not_exists`), and a lost race is a 409 (fix/bugs-2026-11-06).
- 2026-11-06: pnpm 12 runs dependency install scripts only for packages in `allowBuilds` (pnpm-workspace.yaml); everything else is skipped, and the install fails with ERR_PNPM_IGNORED_BUILDS when a package needs its script. Rule: a new native dependency gets added to `allowBuilds` in the same PR (PR #38).
- 2026-11-06: The repo had no STATE.md, so "is it deployed?" needed a trip through workflow runs (Deploy is always skipped). Rule: STATE.md records deploy status, and code PRs update it (CI `state-guard`).
- 2026-11-01: Dependabot opened Tailwind 3 to 4 as a plain bump (PR #30); v4 changes the config model. Rule: framework majors with migration guides get closed and done as a planned change, not auto-merged.
- 2026-09-29: Two borrowers could both take the last unit of an item. Rule: availability changes are one conditional DynamoDB transaction, and a closed garage is checked inside it (PR #20).
- 2026-09-28: Photo S3 keys embedded the uploader's phone number, so deleting an account left PII in object keys. Rule: object keys use opaque IDs only; migrate old keys with `scripts/migrate-photo-keys.ts` (PR #18).
- 2026-09-27: Cognito SignUp was open to anyone and the API trusted a caller-supplied phone. Rule: identity is the verified phone in the ID token, accounts come from invites only (PRs #12, #14).
- 2026-09-27: Data export could be emailed to any address the caller named. Rule: exports are direct downloads to the signed-in user (PR #11).
- 2026-09-27: Each OTP challenge retry sent a new SMS, costing money and enabling SMS pumping. Rule: one code per sign-in, reused across retries (PR #9).
- 2026-09-27: Presigned uploads had no size cap. Rule: sign the declared Content-Length into the URL and enforce a per-user daily quota (PRs #10, #13).
- 2026-09-26: Members could see donor and voter phone numbers. Rule: phones are visible to admins only; clear client caches on sign-out (PR #3).
- 2026-09-26: After the move to the workshop144 org, gitleaks-action needed a paid org license and two tests failed on Saturdays because they read the real clock. Rule: run the pinned gitleaks CLI, and pin the clock in any date-dependent test (PR #2).
- 2026-09-26: Tenant name, site and time zone were hard-coded, putting a real place into a public repo. Rule: per-deployment identity lives in repo variables, never in code or docs.
- 2026-04: `z.url()` accepted `javascript:` URLs, a stored XSS vector. Rule: URL fields use `HttpUrl`, rendering uses `safeHref()` (see CLAUDE.md).
- 2026-04: `actions/upload-artifact` skipped the `.lighthouse/` dot-directory and ubuntu-24.04 runners lack Chrome. Rule: set `include-hidden-files: true` and install Chrome explicitly in CI.
